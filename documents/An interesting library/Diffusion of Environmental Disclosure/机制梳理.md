# Mechanism

## M1 事务所内部形成的统一的工作规则（如披露模板）会影响企业的披露表述

### M1.1 事务所会成为其客户群的common hub

Francis这篇文章说BIG 4会投入高昂的固定成本编写内部技术指南，而这些指南不仅供一线审计员核查使用，还会通过付费订阅或客户服务网络直接提供给客户公司的管理层（CFO及财务团队）。当客户公司面临新的或复杂的披露要求时，为了降低合规成本与被出具非标意见的风险，管理层会直接采纳审计师指南中的披露范例。

```
例如：一家客户公司的 CFO 在编制报告遇到复杂或新型的披露议题（例如新准则落地、环境负债评估、气候风险披露等）时，通常会主动向其所属四大事务所的技术部门寻求指导。
```

### M1.2 个体审计师会受到事务所的规则限制

当一线审计团队的成员使用相同的软件模板去审核不同客户的报表与披露时，系统预设的重要性阈值（Materiality thresholds）和合规性检查项会迫使审计师按照模板让不同客户删除不符合该所风格的披露表述，或补充该所系统要求的关键披露要素。这种技术系统的刚性约束，使得共享同一审计事务所的企业在披露的特性上趋同。

## M2 客户把披露工作交给审计师，审计师再把经验复制给其他客户

### M2.1 客户自身的披露质量参差不齐，需要审计师复核并修改

一些公司可能本身财务能力不足，还有的是不认真完成披露任务，指望审计师修改。Mauritz的文章中通过访谈了 8 位项目合伙人，讲到了具体影响披露的操作：

```
1. 把审计核对清单交给客户，客户按清单补话题，结构因此趋同。
2. 直接让客户去看其他客户或竞争对手怎么写。
3. 指出缺哪一类话题，并给出“可以这样写”的替代表述；管理层通常照收。
4. 用邮件给出替代措辞，理由是降低诉讼风险、满足准则。
5. 在稿子上蓝笔修改。
6. 小客户编制能力不足时，项目组与客户一起改管理层报告，极端情况下由审计师落笔。受访者把这称为审计和咨询之间的灰色地带，也是职业道德上的自我复核风险。
```
